# Masthead — DESIGN.md

> A small, opinionated **letterpress** design system for things one person ships
> on a Tuesday — articles *and* the apps around them. Cool rag paper, blue‑black
> ink, twelve gemstone accents, hairline rules. Print has relief: a pressed
> button is debossed into the sheet, the badge is a seal affixed a hair proud of
> it, a menu is a loose sheet laid on top — everything else flat.
>
> Format follows the [DESIGN.md convention](https://getdesign.md). Visual catalog:
> `index.html` (light + dark, every token and component, and use‑cases).
> Source is split CSS behind one entrypoint, `masthead.css`. Upgrading from
> v0.1: see [MIGRATION.md](MIGRATION.md).

---

## 1. Visual Theme & Atmosphere

**Mood.** An 1890s pattern book / mail‑order catalogue, modernised. Typographically
literate, restrained, quietly ornamented — *Edward Tufte meets a foundry specimen*.
Print is the governing metaphor: if print wouldn't do it, neither do we.

**Two registers.** A screen people work in all day and an article people read are
set differently, the way a printer sets a ledger and a book. The **app register**
(the root) is compact chrome: one UI size, a 4px ruler. The **reading register**
(`.prose`) is the book: a 24px body, a generous heading ladder, long‑form rhythm.
Both are the same system — the same tokens, remapped (§3) — so every app looks
the same.

**Density.** Comfortable, not airy. Hairline rules do the structural work that
boxes and shadows do elsewhere.

**The one philosophy that explains everything else — the boundary.**
A component is a **sealed box**. It owns how it looks and how its *own* parts are
arranged inside it. It never owns *where it sits*.

| System owns (intrinsic) | Caller owns (extrinsic) |
| --- | --- |
| padding, border, radius, own height | margin, position in parent |
| colour, background, type, state | width / max‑width as a layout constraint |
| `display`/`gap` arranging its **own** sub‑elements | `gap` between sibling components |
| `:hover` `:active` `:focus-visible` `:disabled` | grid/flex placement, breakpoints, page rhythm |

**What "margin" means here.** The forbidden thing is **outer / layout margin** —
margin on the component root (or a `>` child) that pushes it around within the
caller's layout. *Intrinsic* spacing is fine and expected: padding, internal
`gap`, and **sub‑glyph nudges on generated content** — e.g. the `0.4em`
`margin-right` on `.press-masthead`'s `::before` accent dot, or the `0.15em`
`margin-left` on `.text-link.-reference`'s `::after` arrow. Those are part of how
the glyph is *drawn*, not where the component *sits*; they ship with it. The one
scope whose job *is* spacing is `.prose` (§3): it sets the vertical rhythm
between its own children, never its own margin or measure.

*Why:* the costliest design‑system bug is a component that looked right in the kit
and wrong in the product because it carried its demo's margins. Refuse layout and
every component is trustworthy everywhere; spacing bugs are never component bugs.

**Methodology.** [RSCSS](https://ricostacruz.com/rscss/), strictly: two‑word
component names (`.press-button`), single‑word `>` child elements, `-`‑prefixed
variants (`.-accent`), `_`‑prefixed helpers (`._sr-only`, `!important` allowed),
one component per file, shallow selectors. Theming is two‑layered: immutable
primitive ramps → semantic aliases the theme remaps. Components read **only**
semantic aliases.

## 2. Color Palette & Roles

All colour is **OKLCH, computed from one formula** — no hand‑picked hexes.

### Gem primitives

Twelve gems, hues deliberately spread so none reads alike. Each is a full **50–900
tonal ramp** generated by one shared lightness scale × one chroma multiplier
(peaks at 500, tapers both ends) × the gem's `{hue, peak‑chroma}`:

```
--gem-<name>-<step>: oklch(L  calc(mult × peakC)  hue)
```

(The gem ramps are fixed primitives — `--accent-chroma` is **not** applied here.
It multiplies the *accent* ramp only, to mute it in dark mode.)

| Gem | Hue | Gem | Hue | Gem | Hue |
|---|---|---|---|---|---|
| ruby | 25° | peridot | 128° | lapis | 280° |
| carnelian | 47° | emerald | 158° | amethyst | 310° |
| amber | 70° | malachite | 185° | tourmaline | 350° |
| citrine | 95° | turquoise | 213° | | |
| | | sapphire | 250° | | |

*Retuning* a gem = two numbers (its `{hue, peak‑chroma}`). *Adding* a gem = a
`{h,c}` pair **+ a 10‑step ramp block** (the `oklch(...)` lines, mechanical) **+
one `[data-accent]` row**. `tint/base/deep` ≈ steps `100/500/800`.

### Neutral primitives

Two separate OKLCH ramps, 50–900: **`--paper-*`** (cool blue‑white, *never cream*)
and **`--ink-*`** (blue‑black, *never pure/OLED black*).

### Semantic aliases — the colour tokens components read

Names are stable; values remap by `data-theme`. `data-accent="<gem>"` re‑points
`--accent-h/-c`; the accent surface is **recomputed per element** under a universal
selector (`*, *::before, *::after`), so a `data-accent` on *any subtree* retints
it. (A custom property's `var()` chain is substituted where the property is
declared; a `:root`‑only ramp would freeze to the root's hue. The universal
declaration is what makes per‑subtree accent — and the accent‑derived
`--accent-solid`, `--selected` and `--focus-ring-color` — actually work.)

| Token | Role | Light | Dark |
|---|---|---|---|
| `--paper` / `-sunk` / `-edge` | surfaces, recessed→raised | `paper-50/100/200` | `ink-900/800/700` |
| `--surface-raised` | a loose sheet: menu, popover, dialog (§6) | `paper-50` | `ink-800` |
| `--scrim` | the tissue guard behind a modal | `--paper` at 72% | same |
| `--ink` / `--ink-2` / `--ink-3` | text: primary / secondary / faint (≈18 / 10 / 5:1) | `ink-900/500/300` | `paper-100/500/700` |
| `--rule` / `--rule-soft` | hairlines | `paper-300/200` | `ink-600/700` |
| `--rule-strong` | firmest stroke — **never pure ink** | `ink-700` | `paper-400` |
| `--hover` | hover wash, relative to whatever is beneath | `--ink` at 5% | same |
| `--selected` | selected row / item / pressed toggle | `--accent-tint` | same |
| `--accent` | accent for marks / edges (and the wordmark) | `accent-500` | `accent-500` (theme‑independent) |
| `--accent-solid` | filled control (`.press-button.-accent`) / reverse‑type bar | `accent-600` | `accent-600` |
| `--accent-on` | label knocked out of `--accent-solid` | `paper-50` | `paper-100` |
| `--accent-tint` / `-soft` / `-deep` | wash / hover / edge & accent text | steps `100/200/800` | steps `800/700/300` |
| `--accent-chroma` | accent‑ramp chroma multiplier (dark muting) | `1` | `0.78` |
| `--ok` `--warn` `--err` `--info` | status **marks and rules** — gems with intent | emerald·amber·ruby·sapphire **500** | **same 500** |
| `--ok-ink` … `--info-ink` | status **text** — AA on `--paper` and `--paper-sunk` | step **600** | step **400** |
| `--ok-tint` … `--info-tint` | status washes | step `100` | step `800` |
| `--focus-ring-color` | the focus ring | `--accent` | same |

**Ink carries hierarchy.** At one UI size (§3) the three text inks have to do the
work size used to do, so they are spread wide — about **18 / 10 / 5:1** against
`--paper` in both themes — and all three clear AA on `--paper` and
`--paper-sunk`. On a `--selected` ground (an accent tint) only `--ink` and
`--ink-2` hold AA in both themes; keep `--ink-3` and the status inks off it.

**Marks vs. text.** A mid gem can't be both a vivid mark and legible text on both
papers, so status is split: the **500s** are for glyphs, rules and fills; words
are set in the **`*-ink`** tokens, remapped by theme the way `--accent-deep` is.
Likewise `--accent` is a mark colour (and the masthead wordmark — a logotype);
accent‑coloured *text* uses `--accent-deep`.

**`--accent` vs `--accent-solid`.** Because the ramp's lightness is
**hue‑uniform**, the fixed `accent-600` clears WCAG **AA** against `--accent-on`
for all twelve gems at once — no per‑gem tuning. Dark mode mutes **only the
accent** via `--accent-chroma: 0.78` (a candle, not a screen), not by changing
steps; the gem primitives and the status 500s are unchanged between themes.

### Public token contract

The split is **who may read what**, not public vs private:

- **Components** read **only** the semantic aliases above (never a raw ramp step).
- **Callers** may read the wider surface. All of this is intentional public API:
  - colour: every gem/paper/ink ramp step (`--gem-<name>-50..900`,
    `--paper-50..900`, `--ink-50..900`, `--accent-50..900`) and every semantic
    alias above;
  - type: `--text-ui`, the register‑mapped `--text-body` / `-subhead` / `-h4` /
    `-lede` / `-h3` / `-h2` / `-display`, `--display-1/2/3`, the two font
    families, `--weight-*`, `--leading-ui` / `-prose` (and the rest of
    `--leading-*`), `--track-caps` / `--track-display`;
  - space and shape: the `--space-*` ruler, `--control-h`, `--radius-0/1/2`,
    `--rule-1/2/3`, `--focus-ring-width` / `--focus-ring-offset`;
  - depth and motion: `--overlay-lift`, `--plate-lift`, `--deboss`,
    `--sheet-1/2`, `--stack-shift`, `--layer-sticky` / `-dropdown` / `-toast`,
    `--duration-1/2`, `--ease-out` / `--ease-in`;
  - icons: `--icon-ui`, `--icon-stroke`.

  These exist so a caller can build what Masthead doesn't ship — a menu, a
  dialog, a toast, a command palette — and have it match: a loose sheet is
  `background: var(--surface-raised); border: var(--rule-1) solid var(--rule);
  box-shadow: var(--overlay-lift); z-index: var(--layer-dropdown)`, its rows
  `font-size: var(--text-ui); line-height: var(--leading-ui)` with
  `--hover` / `--selected`, entering over `var(--duration-2) var(--ease-out)`.

**Stability.** The semantic aliases are the stable promise — build on them and a
theme/accent swap Just Works. The raw ramps are public but **formula‑bound**: a
deliberate, announced ramp retune (the twenty `--ramp-l-*`/`--ramp-c-*` numbers)
moves every step at once, by design. Internal and not contracted:
`--feat-serif` and component‑local custom properties
(`--press-*`, `--tick-*`, `--switch-*`).

### Roll your own palette

The ramp shape is itself public, so a caller can mint a conventionally‑named
palette on the exact same formula without colliding with Masthead's gem names
(gem names are **Masthead's**; name yours `--red-*` / `--green-*` / a brand name):

```css
:root {
  /* one hue + one peak chroma, same recipe as a gem */
  --red-50:  oklch(var(--ramp-l-50)  calc(var(--ramp-c-50)  * 0.19) 25);
  --red-500: oklch(var(--ramp-l-500) calc(var(--ramp-c-500) * 0.19) 25);
  --red-900: oklch(var(--ramp-l-900) calc(var(--ramp-c-900) * 0.19) 25);
  /* …50..900… */
}
```

To make a custom palette the accent, bind its `{hue, peak‑chroma}` to the accent
inputs on the subtree (instead of a `data-accent`): `--accent-h: 25;
--accent-c: 0.19;` — the accent surface recomputes from there exactly as it does
for a gem.

**No generic blue/red/green *in components*. No status‑badge component.** Colour is
rationed; the recipe is open, the components stay disciplined.

## 3. Typography Rules

Two families, **self‑hosted** (`fonts/`, copied to `dist/fonts/` by the build and
loaded by `@font-face` in `masthead.css`):

| Family | Role |
|---|---|
| **EB Garamond** (serif) | everything: body, prose, the heading ladder, and every label, button, seal and table — chrome included |
| **IBM Plex Mono** (mono) | code, `kbd`, serials |

### One root, two registers

The root is the browser default — `html { font-size: 100% }`, 16px for most
readers — so `1rem` means what every other library expects and rem‑sized
third‑party widgets (date pickers, editors, charts) render at their own size.
Everything is rem, so it all scales with the reader's font‑size setting. px is used
only for hairlines; `em` only for sub‑glyph nudges (and `.prose` rhythm, below).

**Registers are a token remap, exactly like `data-theme`.** The root carries the
**app** values; `.prose` remaps the same names to the **reading** values.
Components and the `.t-*` roles read the names, so they set whichever register
applies. Tokens are named by role, not size — a retune never makes the name lie.

| Token | App (root) | Reading (`.prose`) | Role |
|---|---|---|---|
| `--text-ui` | **16** | 16 (never remaps) | **every chrome part** |
| `--text-body` | 16 | **24** | body, `p`, `.t-body` |
| `--text-subhead` | 18 | 20 | `h5`, `.t-subhead` |
| `--text-h4` | 19 | 29 | `h4`, `.press-masthead` title |
| `--text-lede` | 20 | 32 | `.t-lede`, card title, blockquote |
| `--text-h3` | 22 | 39 | `h3` |
| `--text-h2` | 26 | 53 | `h2`, `.t-heading` |
| `--text-display` | 32 | 72 | `h1`, `.t-display` — one page title per screen |

(px at the 16px root.) `.prose` also sets the body size and
`--leading-prose` (1.55) on itself, restores **old‑style figures**, and supplies
long‑form rhythm between its children (`> * + *` 1.1em, headings 1.9em above and
0.5em below, in `em` so it follows each element's size). The **measure** stays
the caller's. Opt‑in fluid heroes: `--display-1/2/3` (`clamp()` between two
steps), re‑resolved inside `.prose`.

### One UI size

Every chrome part — buttons, labels, inputs, selects, table cells and heads, card
body and foot, nav, toggle words, seals, `.t-meta` — is set at **`--text-ui`**.
There is no meta step. A printed page is set in one size and gets its hierarchy
from italic, small caps, ink and rules; so does Masthead's chrome:

- **Small caps for labels.** Form labels, table heads, card feet, running heads,
  toc meta, `blockquote cite`, the seal, the button label, `h5` and `.t-subhead`
  use `font-variant-caps: all-small-caps` — EB Garamond's real `smcp` + `c2sc`,
  never faked, tracked by `--track-caps` (0.06em). **Never `text-transform`** on
  anything that carries user content: the author's case survives, so "API" and
  "api" stay different.
- **Italic + `--ink-3` for meta** (`.t-meta`, `.hint`, the toggle's margin words).
- **Ink for weight of voice** — the wide `--ink` / `-2` / `-3` spread (§2).
- **Rules** for structure.

The exceptions to one size are stated once: the heading ladder (in either
register) and one page title per screen. Nothing else changes size.

**One optical size across the two families.** `body` sets
`font-size-adjust: 0.4` — EB Garamond's x‑height — so Plex Mono (and any
fallback face) is scaled to match the serif at the same nominal size. Code, `kbd`
and `.t-mono` therefore sit at `1em` with no per‑element shrink.

**The heading ladder.** `h1`–`h4` are **serif, sentence case**, descending the
scale; `h1` is light (`--weight-regular` — the title voice is quiet, not loud),
`h2`–`h4` medium. `h5` is the **small‑caps subtitle** (`--text-subhead`,
`--ink-2`; medium as `h5`, regular as `.t-subhead`); `h6` is a **quiet italic heading** at `--text-ui` in `--ink-2`. The
treatments are detachable as `.t-display` / `.t-heading` / `.t-subhead` — apply
where **tag ≠ size**: a hero line that is semantically an `h2`, or an app `h1`
that must stay restrained. Pairing `.t-subhead` with `color: var(--accent)` (the
red‑subtitle look) is the **caller's** call — one accent per surface (§7). There
is no eyebrow style.

**Weights** are pulled **down** (Garamond goes heavy fast): regular 400 / medium
460 / semibold 520 / bold 600, and `font-synthesis: none` (never fake a weight).
Labels and button labels are medium; the `.cancel-stamp` lettering is the
heaviest type in the system, bold 600. Nothing goes above 600.

**Leading** loosens as the line lengthens: `--leading-tight` 1.05 (display),
`--leading-snug` 1.18 (headings), `--leading-ui` 1.375 (chrome — the body
default), `--leading-normal` 1.45 (lede, blockquote), `--leading-prose` 1.55
(`p` and `.prose`). Headings `text-wrap: balance`, body `text-wrap: pretty`.
Tracking: `--track-display -0.01em` (big serif tightens a hair), `--track-caps
0.06em` (every small‑caps context).

**Figures.** Chrome sets data, so the default is **lining** (`body` sets
`font-variant-numeric: lining-nums`); `.prose` restores **old‑style** for running
text. Table number cells (`.-numeric`) and `.t-tabular` are tabular lining.
`--feat-serif` (kern, liga, calt) no longer carries a figure feature, so
`font-variant-numeric` alone controls figures — never override
`font-feature-settings` just to get lining figures (it drops kerning and
ligatures).

**Small‑cap trim (system rule).** Block small‑caps contexts — `h5`,
`.t-subhead`, the form label, the table head and the seal —
apply `text-box: trim-both ex alphabetic`, trimming the line box to the
small‑cap band so **symmetric, ruler‑based padding** centres the lettering.
The trim only reaches block containers: the seal is therefore `inline-block`,
and the button — a flex container, so its label never receives the trim —
carries a measured optical nudge instead (`0.18em` extra bottom padding, the
icon shifted back down `0.09em`). Inline contexts (`.text-link.-runninghead`, `.toc-row` meta, the card foot,
`blockquote cite`) are not trimmed. Browsers without `text-box` ignore it and
fall back to the untrimmed rendering — non‑breaking.

Sentence case for prose and headlines. Em dashes, curly quotes, Oxford comma.
**No emoji** — Unicode ornaments only (`❦ ❧ ✦ § ¶ №`).

## 4. Component Stylings

RSCSS, one file each under `components/`. **No component sets margin, width, or
position.** States are `:hover` / `:active` / `:focus-visible` / `:disabled`, plus
the ARIA states listed per component. Focus is one ring everywhere:
`var(--focus-ring-width) solid var(--focus-ring-color)` at
`var(--focus-ring-offset)` (2px / accent / 2px).

### `.press-button` — a typeset button
A small‑caps Garamond label (`--text-ui`, medium) set in a hairline
`--rule-strong` frame with 2px corners, square in the line. Height is
`--control-h`, so it lines up with boxed inputs and selects in one bar.
**Hover** lays the `--hover` wash over the ground; **press** is a **deboss**
(`--deboss`, §6). Nothing transforms, leans or scales.
- **default (secondary):** ink label, hairline frame, transparent ground.
- **`.-accent` (primary):** filled `--accent-solid`, `--accent-on` label; every
  `data-accent` flows through.
- **`.-ghost` (tertiary):** the label alone, no frame.
- **`.-danger` (destructive):** `--err` frame, `--err-ink` label; combine with
  `-ghost` for a quiet destructive row action. (Not with `-accent`.)
- **`.-icon`:** square, icon only — give it an `aria-label`.
- **`.-small` / `.-large`:** a shorter (24px) / taller (40px) `--control-h`; the
  label stays `--text-ui`.
- `> .icon` (an inline `<svg>`): `--icon-ui` square, `--icon-stroke`, currentColor.
- **`[aria-pressed="true"]`** is a stable state: the deboss held, on the
  `--selected` ground. Use it for toggles and segmented choices.
- **Disabled:** spent — `--ink-3` label, `--rule` frame, no wash, no deboss.
  Both `:disabled` and `[aria-disabled="true"]` are styled; **in apps use
  `aria-disabled`**: the button stays focusable and hoverable, so assistive tech
  announces it and a tooltip can say why it's unavailable.

### `.form-field` — label over control, with hint and error
`> .label` (small caps, `--ink-2`, x‑band trimmed) · `> .input` (an `<input>`,
`<select>` or `<textarea>`) · optional `> .hint` (italic `--ink-3`) and
`> .error` (`--err-ink`; link it with `aria-describedby`).
- **Default:** a ruled writing line in ink. **Focus** turns it into a real **2px
  accent underline** (the line is the field's own focus mark).
- **`.-boxed`:** a mail‑order entry box; focus turns the box accent.
- **Invalid:** `.input[aria-invalid="true"]` or `:user-invalid` turns the line or
  box `--err`, focused or not.
- **`<select class="input">`** draws its own small ink chevron; **`<textarea
  class="input">`** is three control‑heights tall, vertical resize.
- **Radios:** a `<fieldset class="form-field">` with a `<legend class="label">`
  and one `<label><input type="radio"> Text</label>` per choice — a printed
  circle filled with an ink dot when chosen. (Round on purpose: a choice mark,
  not a frame.)
- **`.-inline`:** a settings row — label (and hint / error) on the left, the
  control on the right at its own size.
- Controls are `--control-h` tall.

### `.tick-box` — a tick written into a printed form box
Replaces the browser's `<input type="checkbox">`. Hairline‑bordered paper cell;
on check, two ink strokes draw on in sequence — a short bite, then the long
sweep (~280ms, transition‑driven so a pre‑checked input never flickers on
initial paint). Toggle off reverses the same draw. **`:indeterminate`** (set by
script, `input.indeterminate = true`) lays the sweep level across the box — the
"some of these" mark for a select‑all head. `.-accent` retints the ink to
`--accent`. Sized in `em` so the box tracks the caller's font‑size; the caller
wraps it in `<label>` and the natural inline whitespace handles the gap.

### `.toggle-switch` — a pip riding a hairline rail
The quietest reading of a switch: the track is a single hairline rule, the state
is a small ink pip that slides its length, and the two positions are **named in
the margin** — italic serif `off` / `on`. The active side firms from `--ink-3`;
thrown, `on` takes `--accent-deep` and the pip + rail go `--accent`. Built on a
bare `<input type="checkbox">` the caller wraps in `<label class="toggle-switch">`.
The margin words are generated with **empty alt text** (`content: "off" / ""`), so
they stay out of the accessible name; name the setting with
**`aria-labelledby`** on the input, pointing at the setting's visible label (the
`.form-field.-inline` row is the natural home).

### `kbd` — a key legend printed into the sheet (bare tag)
Not a classed component — the bare `<kbd>` tag, styled in `base.css`. A hairline
cell on recessed paper (`--paper-sunk`), mono at the host size (matched by
`font-size-adjust`), **flat**: a raised 3‑D keycap would be a depth cue outside
§6, so the key reads as *printed into* the sheet.

### `.paper-card` — a sheet of paper, flat by default
`> .title` `> .body` `> .foot`. Elevation = literal stacked sheets behind it,
**no blur, no rotation**, each deeper sheet darker (`--sheet-1`, `--sheet-2`),
drawn as hard box‑shadows so they survive inside any panel with its own
background. *Use which:* **flat** = the default (content in the page);
**`.-stack-1`** = "more behind this" (a set, a pinned item); **`.-stack-2`** = a
heavy pile (sparingly, never a whole grid); **`.-framed`** = a quiet doubled‑rule
plate, combinable with either stack.

### `.data-table` & `.toc-row`
A catalogue table in a **wrapper**: `<div class="data-table"><table>…</table></div>`.
The wrapper scrolls a wide table sideways; the table stays a real table and fills
it. Small‑caps heads over a `--rule-strong` underline, hairline rows,
`--text-ui` cells.
- **Sticky head** within the wrapper (give the wrapper a `max-height` to scroll
  the body under it).
- **`tbody tr:hover`** takes `--hover`; **`tr[aria-selected="true"]`** takes
  `--selected` (both can show at once).
- **`th[aria-sort]`** draws ↑ / ↓ (decorative; `aria-sort` names the order).
- **`.-numeric` on a `th`/`td`** right‑aligns it with tabular lining figures —
  put it on every cell of a number column.
- **`tfoot`** is a totals row under a firm rule.
- Focusable rows and cells ring *inside*, so the scroller never clips a ring;
  controls in cells keep the normal ring within the cell padding.

`.toc-row` (`> .leader` dots + `> .meta`, the meta in small caps) is an
**article‑contents line** — section title + reading‑time, *not* page numbers.

### `.press-masthead` — the namesake
An **italic serif accent wordmark** (`--text-h4`, ~19px) left, roman links at
`--text-ui` right, an **accent dot** before `a[aria-current="page"]`, one hairline
beneath. Case is the author's — nothing is lower‑cased. At narrow widths it
stacks (§8).

### `.cancel-stamp` — an affixed seal (the only badge; no status badges)
A small printed plate **applied** to the sheet: Garamond **600 small caps** at
`--text-ui` on an `--accent-tint` ground, an `--accent` border, `--accent-deep`
lettering, sitting a hair proud on `--plate-lift` (§6). Its corners are
**softly rounded** (~6px: a stuck‑on label, the one component allowed past the
2px radius ceiling); no lean. Retint with `data-accent` on the stamp or any
ancestor. Keep it for the one status that deserves a seal, not a column of fifty.

### `.text-link` — marginalia, flat, always affordant
default (hairline underline, accent on hover) · `.-reference` (italic + ↗,
underline matched to default) · `.-runninghead` (small‑caps tracked nav: section
pagers, footers, in‑page jumps). **Bare `<a>`** follows the register: in chrome
it is unadorned until hover; in running text (`p`, `.prose`) it carries the
hairline underline at rest. Use `.text-link` when a link must always look like one.

### Primitives & helpers
Type roles `.t-display/-heading/-subhead/-body/-lede/-mono/-meta/-tabular`;
the reading register `.prose`; `.rule` / `.rule-thick` / `.rule-double`;
`.fleuron-divider`; `.ornament`. Helpers: `._sr-only` (the only helper;
`!important` allowed here alone).

### Deferred — documented, intentionally not built
Drop cap (per‑article editorial, not a primitive); instrument gauge; a flat
status mark; segmented control; app‑shell pieces (compact top bar, sidebar items,
tabs, breadcrumbs); `.text-link.-folio` / `.-manicule`; the **Press Ornaments**
tier (cartouche, ticket/perforation, vertical‑type, serial, microtype).
Meanwhile they are caller CSS on the public tokens (§2).

## 5. Layout Principles

**Layout is not the system's job (§1).** The system never emits outer margin,
never caps width, never positions itself.

- **Spacing:** a **4px rem ruler**, contiguous `--space-1` … `--space-12`
  (`0.25rem` … `3rem`) plus `--space-16`, `-20`, `-24`. Used **only** for a
  component's intrinsic padding and its *own* internal `gap`. Never margin.
- **Control height:** `--control-h` (2rem, 32px) — buttons, boxed inputs and
  selects share it so a filter bar lines up.
- **Radii:** almost none. `--radius-1: 1px`, `--radius-2: 2px` is the ceiling for
  cards, inputs and buttons. Two sanctioned in‑component exceptions: the
  `.cancel-stamp` seal's softly rounded ~6px corners (a stuck‑on label) and the
  radio's circle (a choice mark). No pill, no token above 2px.
- **Rules:** `--rule-1/2/3` weights; the firmest *colour* is `--rule-strong`
  (≈`ink-700`), never jet‑black.
- **Files:** `masthead.css` `@import`s
  `tokens/{colours,type,space,shadows,motion}.css` → `base.css` (reset +
  bare‑tag appearance + primitives, including `.prose`) → `components/*` →
  `helpers.css` (the only `!important`). One link for a consumer.
- **Long‑form rhythm** is `.prose`'s; the reading **measure** (`max-width`) is
  always the caller's.

## 6. Depth & Elevation

**Print has relief; screens have gloss. We take the relief and refuse the
gloss.** The lamp is fixed at the upper-left, so every cast falls
down‑and‑right and every recess is shadowed on its upper‑left wall. Three
physical depth cues, all in `tokens/shadows.css`, each earned by something
paper actually does:

1. **Stacked paper** — `.paper-card.-stack-1/-2` draw literal duplicate sheets
   behind the card (`--sheet-1`, `--sheet-2`) as hard box‑shadows offset
   down‑and‑right by `--stack-shift`, **no blur, no rotation**. Each deeper
   sheet sits further into shadow (in dark mode rim‑lit slightly *lighter*,
   since nothing beats a near‑black page). Encodes *how much is behind the
   surface*, never interactivity.
2. **The deboss** — type pressed into the sheet. A pressed `.press-button`
   (`:active`, or held by `aria-pressed="true"`) takes `--deboss`: a hard 1px
   inset on the upper‑left inner edge, the recess wall facing the lamp. No
   transform, no scale, nothing beside it moves.
3. **The affixed plate and the loose sheet** — things that sit *on* the page.
   The `.cancel-stamp` carries `--plate-lift` (a hard ink edge + short soft
   drop): a seal a hair proud of the page. A caller's menu, popover or
   dialog is a **loose sheet** laid on top: `--surface-raised` with a
   hairline edge and `--overlay-lift`, a hard, unblurred offset
   down‑and‑right. Behind a modal, `--scrim` is the **tissue guard** — the
   paper‑coloured veil bound in front of a book plate — never a dark dim.

Still categorically refused: glassmorphism, Material elevation tiers, gloss/sheen
gradients, bevels, ambient soft floats, drop shadows on flat type or rules. Depth
is rationed to those three cues and earned by a physical metaphor each time.

## 7. Do's and Don'ts

**Do**
- Read only semantic aliases; theme via `data-theme` / `data-accent`.
- Keep components layout‑free; let the caller place them.
- Set chrome at `--text-ui`; get hierarchy from italic, small caps, ink and rules.
- Put long‑form content in `.prose`; keep the app register everywhere else.
- One accent per surface; let status borrow gems with intent — `*-ink` for words,
  the 500s for marks.
- Hairlines and ink first; let whitespace carry structure.
- Sentence case prose; small‑caps chrome; lining figures in chrome, old‑style in
  prose.
- Prefer `aria-disabled` to `:disabled` for actions in apps.

**Don't**
- ❌ Outer/layout `margin` / `width` / `position` on a component (root or `>`
  child). Intrinsic padding, internal `gap`, and sub‑glyph `margin` on
  `::before`/`::after` generated content are allowed — see §1.
- ❌ Gloss/sheen gradients, bevels, glassmorphism, Material elevation, ambient
  soft floats — depth only via the three §6 cues, never invented elsewhere.
- ❌ Generic blue/red/green; status badges; hard‑coded hex.
- ❌ Status 500s (`--ok` … `--info`) or `--accent` as body text — use the `*-ink`
  tokens / `--accent-deep`.
- ❌ Emoji as icons; pill buttons.
- ❌ Cream backgrounds, pure/OLED black, jet‑black 2–3px strokes.
- ❌ Faked font weights (`font-synthesis`); Garamond above 600.
- ❌ `text-transform` on anything that carries user content; faux small caps.
  Real `all-small-caps` is the label device.
- ❌ A second chrome size, or a third family. No eyebrow labels.
- ❌ Overriding `font-feature-settings` to get lining figures.
- ❌ Hard‑coded `px`/`pt` font sizes or spacing — read the rem `--text-*` /
  `--space-*` tokens. px is for hairlines only; `em` for sub‑glyph nudges.
- ❌ Decoration that doesn't earn its place (no Victorian cosplay).

## 8. Responsive Behavior

**Layout** responsiveness is **the caller's job** — the system never sets
breakpoints for grids, page rhythm, or where a component sits. **Intrinsic**
responsiveness — a sealed‑box reflowing its *own* parts at its *own* size — is
the **component's**, the same family as `gap` and `padding` ("no margins" really
means "no *outer* margins"; likewise "no breakpoints" really means "no *layout*
breakpoints"). The `.press-masthead`'s narrow‑viewport stack (title centred on
top, nav row below, at `40rem`) is the canonical example. A wide `.data-table`
scrolls sideways inside its own wrapper.

- **Type** is a fixed **rem** scale on the 16px root — the same on a phone and a
  desktop, so every app is identical everywhere — and it honours the reader's
  browser font‑size setting (the `--space-*` ruler scales with it). Don't change
  the root per viewport. For heroes that must survive a phone the caller opts
  into `--display-1/2/3` (`clamp()`); the system never bakes viewport coupling
  into a component.
- **Touch targets.** `--control-h` is 32px (24px `-small`, 40px `-large`).
  Masthead does **not** guarantee a 44px target; meeting a platform's minimum is
  the **caller's** hit‑area padding — the system ships the mark, the page sizes
  the target.
- **Collapsing / grids / breakpoints** belong to the consuming page, in its own
  caller‑layer CSS — never shipped.
- **Reduced motion:** all transitions collapse under
  `@media (prefers-reduced-motion: reduce)`.
- **Theme:** `data-theme` may be re‑declared on any subtree; dark mode lowers
  text contrast deliberately (paper‑100, not pure white) to avoid halation while
  holding AA for every text token.

## 9. Agent Prompt Guide

**Setup.** Link `dist/masthead.min.css`. Set the root: `<html data-theme="light"
data-accent="lapis">`. Either attribute can be re‑declared on any subtree.

**Quick reference**
- Accents (`data-accent`): ruby · carnelian · amber · citrine · peridot · emerald ·
  malachite · turquoise · sapphire · lapis · amethyst · tourmaline. Default **ruby**.
- Surfaces: `--paper`, `--paper-sunk`, `--surface-raised`; text
  `--ink`/`--ink-2`/`--ink-3`; lines `--rule`/`--rule-strong`; states
  `--hover`/`--selected`.
- Primary action = `<button class="press-button -accent">`; secondary = bare
  `.press-button`; quiet = `.-ghost`; destructive = `.-danger`; icon‑only =
  `.-icon` with `aria-label`.
- Long‑form content goes in `.prose`; everything else is chrome at `--text-ui`.
- Tables: `<div class="data-table"><table>…</table></div>`; number cells `.-numeric`.
- Status text in `--ok-ink` / `--warn-ink` / `--err-ink` / `--info-ink`; a
  `.cancel-stamp` for the one status that deserves a seal; never a badge.
- Spacing/margins/grids are **yours (the caller's)**, in your own CSS.

**Ready‑to‑use prompts**
- *"Build a devblog article: `.press-masthead`, then an `<article class="prose">`
  with a `.t-display` title and a Draft `.cancel-stamp` seal, a `.toc-row`
  contents list with reading times, fleuron dividers, `.text-link.-reference`
  citations. The caller sets only the measure."*
- *"Build a settings panel: `.paper-card` (flat), `.form-field.-inline` rows
  (toggles named with `aria-labelledby`, selects), a primary `.press-button.-accent`
  and a `.-ghost` cancel. No card elevation; it sits in the page."*
- *"Build a dashboard: a filter bar (a `.form-field.-boxed` search input, a
  `<select class="input">` and a `.press-button`, all `--control-h`), a
  `.data-table` with a select‑all `.tick-box`, `aria-sort`, `aria-selected` rows,
  `.-numeric` amounts and a status column in the `*-ink` tokens."*
- *"Re‑skin this surface to emerald: add `data-accent="emerald"` on the wrapper —
  change nothing else."*

**Hard rules for any generation:** never add `margin`/`width`/`position` to a
Masthead component; never invent depth outside the three §6 cues (no gloss,
bevel, glass, or Material elevation); never introduce a non‑gem colour; never
use emoji; never `text-transform` user content; everything but the pressed
button, the affixed seal and a loose sheet stays flat.
